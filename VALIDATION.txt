Cause and fix
  The 0.5.1 device log recorded sherpa-onnx reporting an absolute model
  tokens.txt path with a non-null AssetManager, followed by a fatal read failure.
  Downloaded models are filesystem files, not APK assets. LocalAsr now passes
  null for the AssetManager, selecting sherpa's file-loading constructor.

Physical-device verification
  Updated the existing installation on Samsung SM-S926B (Galaxy S24+),
  Android 16, using adb install -r. Existing Moonshine model and two pending
  WAV phrases were preserved. Retried those phrases through the app's overlay.
  Logcat showed:
    load moonshine-tiny-en
    loaded moonshine-tiny-en
    decode moonshine-tiny-en samples=29440
    decoded moonshine-tiny-en chars=24
    decode moonshine-tiny-en samples=23680
    decoded moonshine-tiny-en chars=24
  The app process remained alive. No daily note was committed during testing.
  This validates the actual Android arm64 runtime and Moonshine file loading
  and decoding, not every model or the complete recording/save workflow.

Retained checks from 0.5.0/0.5.1
  The APK contains the sherpa-onnx 2.0.1 arm64 runtime but no model weights.
  Earlier host tests extracted all three model archives and transcribed test
  audio using the Linux sherpa runtime. Those host results do not establish
  Android-device behaviour for Whisper or Parakeet.

Not performed
  Whisper and Parakeet inference on the S24+; a fresh live microphone recording;
  end-to-end daily note commit and Syncthing; device restart or lock-screen
  behaviour; stable release signing. Model downloads remain optional.
