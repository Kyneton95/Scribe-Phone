LIVE SERVER PROBE
  Tested the user-supplied endpoint from this host with the user-provided API
  key (the key is deliberately not recorded here). A valid 16 kHz mono WAV was
  POSTed as multipart/form-data with:
    - Authorization: Bearer <key> to /v1/audio/transcriptions
    - Authorization: Bearer <key> to the bare host /
    - X-API-Key: <key> to /v1/audio/transcriptions
    - HTTP/1.1 as well as HTTP/2
  Every POST returned:
    HTTP 200
    content-length: 0
    server: cloudflare
    cf-cache-status: DYNAMIC
  GET / and GET /health initially returned the origin's JSON; GET /docs,
  GET /openapi.json and later POSTs returned the same empty Cloudflare 200.
  This proves the supplied key was not reaching the transcription origin and
  the app was parsing an empty proxy response, not mis-parsing the bearer
  token. The server/proxy must allow POST through, or the LAN URL must be used.

APP CHANGES IN 0.4.3
  - Empty 2xx body now raises:
    "Server returned an empty HTTP N response. Use the full transcription URL
     (for example https://host/v1/audio/transcriptions), or the server's LAN
     URL, and allow POST through Cloudflare/WAF. This is usually a proxy or
     wrong-URL issue, not the token."
  - Empty non-2xx body reports "(empty response)".
  - Non-JSON 2xx reports the HTTP status plus a 240-character body excerpt.
  - Token input is trimmed; an accidental "Authorization:" or "Bearer " prefix
    is stripped before the Authorization header is built.
  - A bare host URL is retried once at /v1/audio/transcriptions after an empty
    2xx response.
  - Added Accept: application/json and User-Agent: Scribe/0.4.3 (Android).
  - Setup now says "API key / bearer token", "Paste the key only (no 'Bearer')"
    and "Use the full path, not the server home page".
